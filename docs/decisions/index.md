## About ADRs

ADRs document significant architectural decisions made in this project. They provide context for why decisions were made and help future contributors understand the reasoning behind the codebase structure.

### When to Create an ADR

- Adding a new major framework or library
- Changing database or storage technology
- Adding new infrastructure dependencies
- Significant architectural pattern changes

### When NOT to Create an ADR

- Minor version bumps
- Dev/test-only dependencies (pytest, eslint, etc.)
- Type definition packages
